# Soro Soro v1.4.0

暮らしの周期と実施履歴を管理する個人用PWA。

- クラウド版: https://sorosoro-backups.dengana-10011212.workers.dev/
- 移行元: https://yuuuh26.github.io/sorosoro/

## バックアップ

端末のIndexedDBに先に保存し、追加・編集・実施・取消・停止・再開・削除・履歴変更・インポートの後、1.5秒待ってクラウドに送信する。オフラインや失敗時は更新番号と送信内容を端末に保持し、次回起動・再接続で再試行。同一処理IDで再送し、送信中の新しい編集を送信済みにしない。Web Locksで同一端末の複数タブの送信を制御する。対応ブラウザはWeb Locks対応のChrome等。

参照だけでは保存を作成しない。初回接続で空の端末データを送らない。既存クラウド履歴がある場合、復元または明示的な手動保存を選ぶまで自動送信を止める。最新データの期限・非利用による削除なし。完全な再取得検証が成功してから最新5件に整理する。

設定に手動保存、前回成功時刻、未送信状態、復元、端末管理、完全JSON書き出し・読み込みを配置。プライベート・停止中の項目もバックアップ対象。複数端末のリアルタイム同期は行わない。現在の端末内容をクラウド履歴として保存する構成。

## 初回移行

1. 旧URLを、記録を入力していた端末・ブラウザで開く。設定の「全データを書き出す（JSON）」を押す。
2. クラウド版を開き、設定で専用の復旧キーと端末名を入力して接続する。
3. 同じJSONを読み込み、件数を確認して復元する。現在のデータは復元前に端末内へ退避し、確認中に他タブ等で編集があれば復元を中止する。
4. 設定の「クラウド保存済み」と成功日時を確認。旧データ・JSONは確認後もバックアップとして保持する。
5. クラウド版をホーム画面に追加する。URLが変わるため、以前のPWAとは別アプリになる。

## 認証

Cloudflare Workersと専用D1。アプリごとにキー・通行証・Cookie・DB・オリジンを分離。復旧キーは256bit乱数で、原文は公開コードや端末データに保持しない。検証用ハッシュをSecrets、キー変更後はD1の専用設定に保存。端末の通行証はSecure/HttpOnly/SameSite=Strictのホスト限定Cookie、DBにはハッシュのみ。サーバー側の一律期限なし、Cookieは利用時に更新。ブラウザの保持制約やデータ削除により再接続が必要な場合がある。

管理操作には毎回復旧キーが必要。端末一覧・名称変更・取消・全取消・キー変更に対応。キー変更は全端末を取り消し、新キーを1回だけ表示する。変更時は直ちに新キーを保存する。サーバー認証、Origin検証、試行回数制限、形式/サイズ検証、CSP、no-storeを適用。認証済みAPI応答をService Workerのキャッシュへ保存しない。

## 開発・更新

`npm install` → `npm test` → `npm run build`。配備時は既存のD1とSecretsを保持し、クラウド版のWorkerも更新する。GitHub Pages更新だけではクラウド版は更新されない。最大スナップショット8MiB、D1行上限を考慮し分割保存。添付画像はない。

`cloudflare/migrations`はバージョン順に適用し、既存DBを初期化しない。Cloudflare管理トークンや復旧キーをリポジトリに含めない。`cloudflare/dist`はビルド成果物でGit対象外。
